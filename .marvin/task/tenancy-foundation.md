# CAPCOM Tenancy Foundation (PR-2)

## Goal

Realize the accepted **ADR 0083** as running code: the multitenant spine
`organization → project`, `membership` + the `owner | admin | analyst | viewer`
RBAC ladder, tenant isolation enforced as a **database invariant** via RLS scoped
through a membership join, the deliberate `auth.users` (member) ≠ `profiles`
(tracked end-user, deferred to PR-3) split, a minimal Supabase-Auth shell, an
org/project switcher, RLS isolation tests on the membership critical path, and a
deterministic seed. No new ADR — the decision is already accepted; this PR is its
first dependent.

## Context

- Decision of record: **ADR 0083** (accepted) fixes the model — shared schema, RLS
  via membership join, `is_member(project)` / `has_role(project, role)` helpers,
  identity split, deny-by-default. PR-2 is its realization; the companion ADRs
  0084–0086 (aggregation / ingestion / charts) land in PR-3+.
- Existing infrastructure consumed: `src/lib/supabase/{server,client,middleware}.ts`
  (request-scoped RLS clients, ADR 0013); `src/proxy.ts` (next-intl + session
  refresh); `src/i18n/navigation` (locale-aware Link/router/redirect, ADR 0030);
  `src/components/ui/{button,badge}` (the shadcn kit); the FSD layers (ADR 0065/0066).
- Constraints: Supabase baseline = Postgres + RLS + Auth only (ADR 0012); migrations
  are plain SQL with RLS versioned together (ADR 0014); types generated, not written
  (ADR 0015); forms = RHF + one Zod schema validating client + server (ADR 0017/0020);
  every user-facing string via next-intl (ADR 0030); merging is human-only (ADR 0046).
- Sibling specs: PR-3 (events/profiles/ingest) builds directly on this migration's
  helpers and the membership join.

## Chosen Approach

Shared-schema RLS with **SECURITY DEFINER** membership-join helpers. DEFINER is the
load-bearing choice: `is_org_member` backs the `memberships` SELECT policy, and a
SECURITY INVOKER helper reading `memberships` from inside that policy raises
Postgres's "infinite recursion detected in policy". DEFINER evaluates the lookup
outside RLS (the standard Supabase idiom), keeps every policy a one-line predicate,
and is safe because the helpers take no caller identity (they read `auth.uid()`
themselves, so a forged argument only narrows), pin `search_path = ''`, and have
execute revoked from `public`. RBAC is a second predicate (`has_role`) over an
explicit `role_rank` ladder, independent of enum declaration order.

The app stays code-first and RLS-scoped end to end: Server Components fetch as the
signed-in user, so the switcher and pages render only what the membership join
permits; the project overview returns 404 for a hidden project, leaking no existence.

## Why this over alternatives

ADR 0083 already weighed schema-per-tenant (B), database-per-tenant (C), and
app-layer filtering (D) and chose shared-schema RLS (A). Within A, the open choice
was INVOKER-with-inline-subqueries vs DEFINER helpers; INVOKER recurses on the
self-referential `memberships` policy, so DEFINER (search-path-pinned, least-privilege)
is the only clean realization of the ADR's "readable one-liner policy" requirement.

## Non-goals

Profiles / events / ingestion (PR-3); aggregations and charts (PR-4+); self-serve
organization creation, member-management UI, and password reset (out of PR-2 scope —
provisioning is seeded); `force row level security` (owner is a bypassing superuser;
reviewer-rated nit).

## Security / NFR

Isolation is a database invariant (deny-by-default, anon ungranted, the client never
asserts tenancy). Helpers are search-path-pinned DEFINER with execute revoked from
public. Auth errors are coarse codes mapped to generic translated copy (no provider
text leaks, ADR 0019). The identity split is structural — no FK to `auth.users` save
`memberships.user_id`.
